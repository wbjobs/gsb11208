# Emoji 兼容性检测台

纯前端、零依赖、零构建的 Emoji 渲染兼容性检测工具。面向需要在多平台正确展示 Emoji 的开发者，检测当前浏览器/系统对基础 Emoji、变体选择符（VS15/VS16）、肤色修饰符、ZWJ 序列、旗帜序列的渲染能力，并对不支持的序列给出语义一致的降级方案。

## 运行

```bash
npm start
```

然后打开 `http://127.0.0.1:5173`。需要通过 `localhost` 或 HTTPS 访问，Clipboard API 才可自动复制（否则弹出手动复制对话框）。

## 测试

```bash
npm test
```

测试覆盖码点格式化、字素簇分割（含 Intl.Segmenter 缺失时的内置降级）、降级方案语义、搜索匹配、合并宽度分类器、UA 解析与数据集完整性。

## 检测原理

- **宽度测量**：在 Canvas 2D 中以固定字号（32px）和 Emoji 字体栈测量 `measureText` 宽度。序列宽度与成员宽度之和的比值用于判断 ZWJ/肤色/旗帜是否被合并为单字形（`classifyMerge`）。
- **像素分析**：将 Emoji 绘制到 Canvas，统计彩色像素占比（区分彩色字形与单色轮廓/豆腐块），并对像素做采样哈希作为渲染签名。
- **豆腐块检测**：与未分配码点 U+10FFFE 的渲染签名比对，签名一致即判定为缺字形。
- **变体选择符**：比较基础字符与「基础字符 + VS16」的渲染签名，完全一致说明选择符被忽略。
- **旗帜**：与两个区域指示字母分别渲染的结果做签名比对，并结合颜色信号，避免把字母显示误判为旗帜。
- **误判防护**：宽度、颜色、签名多信号交叉验证；信号冲突时标记为「存疑」（低置信度），且每个条目支持手动「强制降级 / 强制原生」覆盖，覆盖结果持久化到 IndexedDB。

## 降级方案（语义一致）

- 豆腐块 → `[名称 U+XXXX]` 文本；
- 旗帜不支持 → ISO 3166-1 两字母代码（如 🇨🇳 → `CN`）；
- 肤色不支持 → 去掉修饰符的基础 Emoji（👍🏽 → 👍）；
- ZWJ 被拆分 → 成员组合展示（👨‍👩‍👧 → 👨 + 👩 + 👧）；
- 变体选择符被忽略 → 基础字符。

## 技术栈

- **DOM**：卡片网格、详情对话框、筛选控件；
- **Canvas**：宽度测量与像素级渲染分析；
- **Intl.Segmenter**：字素簇分割（缺失时自动切换到内置降级实现）；
- **IndexedDB**：缓存检测结果（按 UA + 字体栈 + 字号为键）、保存手动覆盖；不可用时降级为内存存储；
- **Web Worker**：在 OffscreenCanvas 中执行批量检测，不阻塞主线程；不支持时回退主线程。

## 文件结构

- `lib/emoji-core.js` — 码点、分割、搜索、降级方案等纯逻辑（页面/Worker/测试共用）
- `lib/emoji-data.js` — 66 个样本，覆盖五大分类
- `lib/detect-core.js` — Canvas 检测与纯分类器
- `lib/storage.js` — IndexedDB 封装（含内存降级）
- `worker.js` — 检测 Worker
- `app.js` — 界面与调度
